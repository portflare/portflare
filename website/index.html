Product

A practical publishing layer for apps that are not ready for the public internet.

Portflare sits between your users and your running apps. The server owns routing and approvals, while clients run next to the workloads they expose.

↗

Security model

Designed around explicit trust boundaries.

Portflare is moving toward auth-service backed registration where authentication is isolated and the server only trusts configured backend identity assertions.

Self-hosted authority Your server owns users, apps, approvals, and API keys.
Provider hub The auth service handles Google first, with room for GitHub and other providers.
Strong handoff Short-lived codes, state validation, PKCE, and signed backend verification.

Quick start

Get from local app to public URL in minutes.

Start with the server, register a client key, then expose a local target. Portflare keeps the client and server responsibilities separate so each piece can be deployed independently.

1. Start the client 
export PORTFLARE_SERVER_URL=https://r.example.dev
export PORTFLARE_CLIENT_KEY=pf_your_key_here
portflare daemon
2. Expose an app 
portflare expose \
  --app web \
  --target http://127.0.0.1:3000
3. Visit the URL 
https://web-alice.r.example.dev
